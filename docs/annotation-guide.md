# 真实提示词采集与标注规范 v1

目标：正式主数据目标 1200 条（每类约 200），最低 600 条。当前正式样本为 0。先采集并试标 60 条，再冻结规则；不足最低量时仅汇报先导实验。

## 采集

优先收集本人或获得研究使用授权的真实编程助手请求。只保留必要的用户请求和前轮用户/助手文字，删除密钥、邮箱、内部地址、个人身份信息和不必要代码。不要扫描其他聊天记录或账号文件。人工导入数据前检查使用许可。

`real_assistant` 表示真实助手请求；`public_proxy` 表示公开问题单等代理材料，必须记录原始链接及许可判断；`synthetic_debug` 只供工具调试，禁止混入正式数据。

`source_group` 应标识不能跨集合的任务来源（例如同一个 issue 或同一个开发任务），不是整个 GitHub 网站；`conversation_id` 标识同一会话。公开代理请求和真实助手提示词分开报告。

## 类别边界

| 类别 | 包含 | 边界 |
|---|---|---|
| explain | 解释代码、分析已有行为和设计 | 明确要求修复行为归 debug_fix |
| debug_fix | 诊断/修复既有缺陷 | 主要交付物是测试代码时归 test |
| test | 新增、修改、修复测试 | 仅解释失败日志而不要求改测试，可归 debug_fix/explain，须结合明确目标 |
| feature | 新增程序行为或新功能 | 恢复预期行为归 debug_fix |
| refactor | 保持主要功能的结构或性能改进 | 修复明确错误归 debug_fix |
| other | 非上述编程任务、无关联日常请求等 | 不等于不知道标签，也不等于模型超时 |

按用户明确要求的主要交付物标注。存在并列且无法确定主次的多意图时，不强行放入单标签主集，转入独立挑战材料并记录可接受标签。任务长度不是难度标准，本轮不标主观难度。

## 试标与复核

1. 先收集 60 条，覆盖六类，标注 rationale（一句理由）与争议点。
2. 统一类别边界后重新检查试标样本，再扩充数据。
3. 近重复、代码改名/表述改写、同一任务连续轮次归入同组。自动校验只处理规范化重复及显式分组，语义近重复必须人工复核。
4. 正式数据逐条完成标注；测试集至少 20% 和全部争议项应由第二人复核。若没有第二人，明确标为单人标注，不制造多人一致性指标。
5. 所有输入 `annotation_status=adjudicated` 只表示标注流程已完成，不能推断有第二位标注者。
6. 采集时不为了凑类别数量改写真实请求。保留原始分布统计，按类别抽样的平衡集只评价分类能力，不能直接估算真实生产分布下成本。

## 挑战集

另收集 180 条、六组各约 30 条：否定转折、多意图、上下文承接、长文本/代码日志、中英混合口语、任务切换/范围外。与主集来源隔离。挑战集的多标签可接受集不使用当前单标签 score 命令计分；专门计分器尚待实现。
